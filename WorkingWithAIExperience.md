# Опыт работы с AI-агентом: визуализация дерева разбора в Kotlin++

## Задача

В проекте Kotlin++ нужно было не просто переводить код,
но и показывать пользователю **дерево разбора (parse tree)**, которое строит ANTLR —
чтобы было видно, как парсер разложил код на грамматические конструкции. Готового решения
не было, была только черновая HTML-страница с некрасивым, горизонтальным и визуально
не связанным деревом.

Для реализации я обратилась к Claude (AI-агент в чате Claude.ai) и вела с ним пошаговый диалог,
показывая текущий код и объясняя, что хочу получить на выходе.

## Идея

Основная идея была простой — **JSON как мост между бэкендом
и фронтендом**:

1. На бэкенде (C#) уже существует дерево разбора ANTLR (`IParseTree`) — внутреннее
   представление, которое не отдать напрямую в браузер.
2. Пишем конвертер (`ParseTreeConverter`), который рекурсивно проходит это дерево и строит
   простую DTO-структуру (`TreeNodeDto`): имя узла + список детей.
3. Эта структура сериализуется в JSON стандартными средствами ASP.NET (`Results.Ok(new {...})`
   сериализует объект в JSON автоматически, без ручного вызова `JsonSerializer`).
4. Fronтенд получает этот JSON в ответе на `/translate` вместе со сгенерированным C++-кодом
   и строит по нему интерактивную картинку средствами **D3.js**.

То есть одна и та же структура данных (`{ name, children }`) проходит путь:
ANTLR-дерево → DTO на C# → JSON в HTTP-ответе → дерево в SVG в браузере.

## Как именно помог AI-агент

### 1. Сам скрипт дерева (D3.js)
Я показала агенту пример JSON и объяснила, что хочу получить. Agent написал с нуля
отдельный файл `tree-view.js`, который:
- строит дерево **вертикально** (сверху вниз), а не горизонтально, как было;
- рисует связи между узлами не прямыми линиями, а плавными изогнутыми кривыми
  (`d3.linkVertical`-подобная кубическая кривая Безье, но подстроенная под низ/верх коробки
  узла, а не под его центр);
- автоматически считает ширину каждого узла по длине текста (через `canvas.measureText`),
  чтобы длинные названия грамматических правил не накладывались друг на друга;
- по-разному стилизует узлы-правила (например, `Statement`, `FunctionCall`) и узлы-токены
  (конкретные лексемы вроде `'val'`, `'+'`);
- поддерживает сворачивание/разворачивание веток по клику и масштабирование (zoom/pan).

### 2. Интеграция с реальным проектом
Дальше агент помог встроить этот виджет не как отдельную демо-страницу, а прямо в существующий
интерфейс (`index.html` / `script.js` / `style.css`):
- кнопка **View Tree**, которая неактивна, пока не выполнен перевод, и включается сразу после
  успешного ответа от сервера;
- полноэкранный оверлей с деревом, который открывается по клику на эту кнопку, используя уже
  полученный JSON — без повторного запроса на сервер;
- стиль дерева агент подогнал под уже существующую светлую тему проекта (тот же синий акцент,
  тот же шрифт Inter, скруглённые карточки), а не оставил как отдельный «чужеродный» дизайн.

### 3. Правки на бэкенде
Когда я добавляла поле `tree` в ответ `/translate`, агент помог поменять `Translator.cs` так,
чтобы метод отдавал кортеж `(string CppCode, TreeNodeDto Tree)`.

### 4. Доп. фича — клик по узлу показывает код
Отдельным шагом я попросила, чтобы при клике на узел дерева появлялся кусок исходного кода,
который этому узлу соответствует. Для этого агент:
- добавил в `TreeNodeDto` новое поле `Source`;
- расширил `ParseTreeConverter`, чтобы он по индексам начального/конечного токена
  (`ParserRuleContext.Start.StartIndex` / `Stop.StopIndex`) вырезал из исходной строки именно
  тот диапазон символов, который покрывает узел — с сохранением исходных пробелов и переносов
  строк (а не просто склеивал текст токенов подряд);
- на фронтенде сделал всплывающую карточку с этим текстом.

Первая версия (широкая панель снизу экрана, появляющаяся на обычный клик) оказалась неудобной —
она мешала обычному сворачиванию/разворачиванию узлов. По моей просьбе агент переделал это на
**правый клик (ПКМ)**: обычный клик снова только разворачивает/сворачивает узел, а код
показывается компактной карточкой рядом с курсором только по явному действию — и сама
закрывается по клику в сторону или по Esc.

## Вывод

Работа с AI-агентом в этой задаче свелась к итеративному диалогу: я показывала текущий код и
описывала желаемый результат, агент предлагал
конкретную реализацию, а я проверяла её в своём проекте и просила поправить то, что не
устраивало (стиль, формат всплывающего окна, способ вызова). Это оказалось быстрее, чем
разбираться с D3.js и ANTLR `ParserRuleContext` с нуля самостоятельно, но финальная
ответственность — собрать, запустить и проверить, что всё действительно работает в составе
всего проекта, — оставалась на мне.
